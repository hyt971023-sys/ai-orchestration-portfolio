# 업무 성숙도 4단계 프레임워크

> **문제** — "자동화해뒀다"는 말은 검증이 불가능한 주장이다.
> 그래서 자동화를 **상태**가 아니라 **단계**로 정의하고, 각 업무가 어느 단계에 있는지 세기로 했다.

## 왜 필요했나

운영 업무를 감으로 자동화하면 두 가지가 동시에 일어난다.

1. **눈에 띄는 일부터 손대게 된다.** 조용히 손실을 내는 일은 계속 남는다.
2. **"자동화했다"의 기준이 사람마다 다르다.** 스크립트를 만든 것과, 남이 쓸 수 있게 된 것과, 사람 없이 도는 것은 전혀 다른 상태인데 전부 "자동화"라고 불린다.

두 번째가 특히 위험하다. 담당자가 자리를 비웠을 때 실제로 멈추는 게 무엇인지 아무도 모르기 때문이다.

## 4단계 정의

| 단계 | 정의 | 판별 질문 | 담당자 부재 시 |
|---|---|---|---|
| ⚙️ **무인 자동** | 사람 개입 없이 정해진 시각에 실행 | 지난주에 아무도 실행시키지 않았는데 돌았는가? | 계속 돈다 |
| 🔧 **도구화** | 명령 1회 실행으로 완료 | 절차를 기억하지 않아도 실행할 수 있는가? | 멈추지만 누구나 재개 가능 |
| 📋 **절차화** | 문서·체크리스트로 인계 가능 | 문서만 주고 남에게 넘길 수 있는가? | 멈추지만 인계 가능 |
| 🧠 **담당자 전속** | 아직 한 사람 손에만 있음 | 이 사람이 없으면 방법을 아는 사람이 없는가? | **멈추고, 재개 방법을 모른다** |

**핵심은 마지막 열이다.** 이 프레임워크의 목적은 자랑이 아니라 **위험 측정**이다.

## 적용 결과

운영 업무 178건을 단위로 분해해 분류했다. 실행 가능한 상태로 유지되는 147건의 분포:

```
⚙️ 무인 자동    ███████                            25건  (147건 중 17%)
🔧 도구화       ████████████████████████████████   96건  (147건 중 65%)
📋 절차화       █                                   5건  ( 3%)
🧠 담당자 전속   ██████                             21건  (14%)
```

**이 표는 두 방향으로 동시에 읽힌다.**

- 위쪽(무인·도구화 82%) = 3개월간 만든 것이 시스템으로 남아 있다는 **증명**
- 아래쪽(담당자 전속 14%) = 이관과 인프라 이전이 필요하다는 **근거**

자랑과 요청이 같은 표에서 나오므로 따로 설득할 필요가 없다.

## 두 번째 지표 — 실행 위치 집중도

성숙도만으로는 부족했다. `무인 자동`으로 분류된 것도 **어디서 도는지**에 따라 위험이 전혀 다르기 때문이다.

그래서 자동화 자산을 **실행 위치**로 다시 셌다. 성숙도와 실행 위치는 서로 다른 축이다.

```
공용 인프라에서 실행   →  담당자와 무관하게 지속
개인 작업 환경에서 실행 →  담당자에게 묶여 있음   ← 여기가 위험 구간
```

`무인 자동`인데 개인 환경에서 도는 자산은 **자동화된 것처럼 보이지만 실제로는 사람 한 명에게 묶여 있다.**
이 축을 만들기 전에는 그 사실이 지표로 존재하지 않았고, 따라서 논의 대상도 되지 못했다.

> 이 축으로 실제로 세어보면 개인 환경에 의존하는 구간은 목록만 훑을 때보다 넓게 잡힌다. **성숙도 축에서 상위로 분류된 자산일수록** 그렇다 — 잘 자동화돼 있을수록 실행 위치를 따져볼 생각을 안 하기 때문이다. 축을 하나로 두지 않은 이유가 여기 있다.

### 측정 규칙 (부풀림 방지)

프레임워크가 신뢰를 얻으려면 세는 방법이 먼저 방어 가능해야 한다.

1. **추정 금지** — 코드·설정 파일을 실제로 열어 확인하고, 모든 행에 근거 경로를 남긴다
2. **자산 단위를 먼저 정의** — 행사별 스크립트 4개는 1자산. 라이브러리는 실행 자산이 아님
3. **모름을 모름으로 보고** — 근거가 없으면 `미확인`으로 남긴다. 추측으로 채우지 않는다
4. **휴면 판정 기준 명시** — 3개월 이상 실행 흔적이 없으면 휴면
5. **조사자와 결정자를 분리** — 유지/이전/폐기 판정란은 비워서 의사결정권자가 채우게 한다
6. **세지 않은 것을 별도 기재** — 조사 범위의 경계를 명시한다

## 측정 도구

이 프레임워크는 문서가 아니라 **도구로도 제공**합니다.

```bash
python -m maturity sample > tasks.csv
python -m maturity report tasks.csv            # 터미널
python -m maturity report tasks.csv -f md      # 문서 붙여넣기용
python -m maturity report tasks.csv -f json    # 파이프라인 연결용
```

측정 규칙이 코드에 박혀 있습니다 — 미확인을 분모에서 빼지 않고, 규격 불일치 행을 조용히 버리지 않고,
**집계 결과가 0건이면 성공으로 끝내지 않습니다.** (0건 성공은 무증상 미수행이므로)

## 다른 조직에 적용하는 법

이 프레임워크는 특정 도구나 업종에 묶여 있지 않다. 필요한 것은 세 가지뿐이다.

```
1. 업무를 "독립적으로 수행하는 단위" 로 분해한다   (파일 개수를 업무 개수로 세지 않는다)
2. 각 단위에 4단계 중 하나를 배정한다              (판별 질문으로 기계적으로)
3. 자동화 자산의 실행 위치를 따로 센다             (성숙도와 실행 위치는 다른 축이다)
```

산출물은 두 숫자다 — **상위 2단계 비율**(자동화 성숙도)과 **개인 환경 실행 비율**(운영 위험).
전자는 성과이고, 후자는 다음에 무엇을 해야 하는지를 알려준다.
