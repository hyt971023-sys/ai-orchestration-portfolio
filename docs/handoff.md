# 이관 설계 — 혼자 쓰는 자동화는 자산이 아니다

> 담당자가 자리를 비우면 멈추는 자동화는 **부채**다.
> 만든 사람에게는 성과로 보이지만, 조직 입장에서는 의존할 곳이 하나 더 늘어난 것이다.

## 이관의 3단계

자동화를 남에게 넘기는 것은 코드를 전달하는 일이 아니다. 세 개가 순서대로 필요하다.

### 1단계 — 실행을 명령 1회로 줄인다
절차를 기억해야 실행할 수 있으면 이관되지 않는다. 인자·순서·전제조건을 도구 안으로 흡수시켜, **이름만 알면 실행되는 상태**로 만든다.

### 2단계 — 판단 근거를 문서로 분리한다
"왜 이렇게 했는가"가 없으면 인수자는 손대는 것을 두려워한다. 결과적으로 아무도 못 고치는 코드가 된다.
설계 결정을 별도 문서로 남긴다 — **무엇을 하지 말아야 하는지**를 특히 명시한다.

### 3단계 — 실행 위치를 사람에게서 떼어낸다
1·2단계를 끝내도 개인 작업 환경에서 돌면 여전히 담당자에게 묶여 있다. 공용 인프라로 옮겨야 이관이 완료된다.

> 이 3단계를 안 밟으면 [성숙도 프레임워크](maturity-framework.md)의 `담당자 전속` 칸에 그대로 남는다.

<br>

## 실제로 만든 이관 산출물

| 산출물 | 무엇을 해결하나 |
|---|---|
| **재사용 스킬 9종** | 반복 업무를 명령 1회로 축약. 팀원이 절차를 몰라도 실행 가능 |
| **공유 저장소 + 커밋 가드** | 지식이 개인 로컬이 아니라 팀 저장소에 축적. 민감정보 커밋을 사전 차단 |
| **운영 정본 문서(SSOT)** | 같은 질문에 두 사람이 다른 답을 하지 않게. 판단 기준을 한 곳으로 |
| **런북 + 킬스위치** | 사고 시 담당자를 못 찾아도 대응 가능. 정지 방법을 먼저 문서화 |
| **설계 결정 기록** | "왜 A가 아니라 B인가"를 남겨 인수자가 되돌리지 않게 |
| **실측 자산 인벤토리** | 무엇이 어디서 도는지 목록화. 이관 대상 판정의 분모 |

<br>

## 이관 실증 — 넘긴 뒤에 확인한 것

만들어 넘기는 것으로 끝내지 않고, **인수자 환경에서 실제로 도는지**까지 확인했다.

```
① 원클릭 설치 스크립트 제작       — 환경 구성이 이관의 실제 병목이었다
② 개인 상태·설정값 초기화         — 만든 사람의 로컬 값이 섞여 들어가는 것을 차단
③ 인수자 환경에서 실행 검증        — 알림 타임스탬프로 실제 동작 확인
④ 기존 담당자 실행 종료           — 두 곳에서 동시에 돌면 충돌한다
```

**④가 핵심이다.** 넘겼는데 원래 것도 계속 돌면 이관이 아니라 중복이고, 두 시스템이 같은 대상을 서로 다르게 바꾼다.

<br>

## 이관 문서가 실제로 쓰이는지 사후 점검했을 때

넘긴 문서가 남아 있다는 것과 그 문서가 쓰인다는 것은 다르다. 사후 점검에서 두 가지가 드러났다.

- 문서는 남아 있어도 **1만 줄짜리 통합본은 급할 때 아무도 안 본다**
- 문서에 적힌 실행 환경이 실제와 달랐다 — **문서와 현실의 드리프트**를 검증하는 절차가 없었다

그래서 이관 문서를 **"찾으면 바로 실행 가능한 상태"** 기준으로 다시 썼다.
길이가 아니라 **진입점에서 몇 번 만에 실행에 도달하는가**로 문서 품질을 판정한다.
