# 케이스 01 — 자연어 오더 → 멀티채널 재고 오케스트레이션

> 채널마다 다른 상품 체계를 정본키로 묶고, 한 줄 지시로 여러 판매처의 판매 가능 수량을 동시에 통제하는 레이어

**증명하는 역량** · 이기종 시스템의 식별자 정합 문제를 해결하고, 되돌릴 수 있는 형태로 일괄 제어를 설계

<br>

## 문제

여러 시장이 **같은 창고를 공유**하는데, 채널마다 상품번호 체계가 전부 달랐다.
재고가 부족하면 담당자가 채널별 관리자에 하나씩 들어가 옵션 수십~수백 개를 손으로 껐다.

여기에 세 가지 함정이 겹쳐 있었다.

| 함정 | 결과 |
|---|---|
| 상품명으로 매칭 | 단종된 구형 옵션이 현행과 이름이 겹쳐, 이름으로 고르면 **엉뚱한 옵션까지 차단하게 된다** |
| 같은 상품의 3종 버전 (구형/리뉴얼 · 내수/수출 · 표기 상이) | 어느 것이 지금 팔리는 것인지 코드가 판단 못 함 |
| 묶음 상품을 물리 재고 그대로 노출 | 세트를 물리 재고로 노출하면 구성품 환산이 빠져 **실재고를 넘는 판매가 구조적으로 가능** |

즉 "재고를 막는다"는 단순해 보이는 작업이, 실제로는 **식별자 정합 문제**였다.

앞의 두 함정은 [재현 데모](../demo/)에 그대로 넣어 뒀다. 픽스처에 `(구형)`·`(단종)` 옵션과 채널별 표기 차이를 남겨서,
**이름은 걸렸는데 정본키가 달라 대상에서 빠지는 과정**이 실행 출력에 찍힌다.

<br>

## 접근

### ① 쓰기 가능 여부부터 전수 조사
설계 전에 채널별로 **조회만 되는지, 수정까지 되는지**를 먼저 확인해 맵을 그렸다.
이걸 모르고 설계하면 실행 단계에서 절반이 수동으로 되돌아온다.

### ② 정본 식별키를 바코드로 확정
상품명이 아니라 **바코드(GTIN)** 를 정본키로 삼고,
`옵션명 ↔ 세트SKU ↔ 구성품 바코드·수량` 크로스워크 사전을 별도로 구축했다.
사전이 없으면 매번 사람이 "이 옵션이 창고의 무엇인가"를 판단해야 한다.

### ③ 우선순위 규칙을 명문화
```
담당자 직접 지시  >  창고 자동 알림
```
규칙이 없으면 자동 알림이 사람 판단을 조용히 덮어쓴다. **어느 쪽이 이기는가**를 코드가 아니라 문서에서 먼저 정했다.

### ④ 부족한 것만 골라 닫는다 ← 내가 틀렸던 지점
**내가 처음 만든 구현은 해당 상품의 전 조합을 닫았다.** 확인해보니 한 옵션만 부족한 상황이었고,
**팔 수 있는 나머지를 스스로 버리고 있었다.** 부족한 조합만 특정해 닫도록 고쳤다.

이 결함은 내가 만든 것이므로 결과에 그대로 남긴다. 그리고 같은 실수를 반복하지 않도록
[재현 데모](../demo/)에서 **조합 단위 매칭(교집합)을 테스트로 고정**했다 — 넓게 잡는 구현은 테스트가 먼저 막는다.

### ⑤ 4중 안전장치
```
1. dry-run       — 무엇이 어떻게 바뀔지 먼저 출력
2. 스냅샷        — 쓰기 전 before 값을 롤백 파일로 저장
3. 실제 차단 경로 — 노출 플래그가 아니라 판매 플래그를 끈다 (품절 표시만으론 안 막힌다)
4. read-back     — 쓰기 후 독립 재조회로 반영 확인 (200 OK 를 반영으로 믿지 않는다)
```

### ⑥ 진열은 유지하고 판매만 끈다
진열까지 끄면 상품이 목록에서 사라져 나중에 찾지 못한다. **되돌아올 경로를 남긴다.**

<br>

## 결과

- 채널별 관리자를 순회하던 작업이 **한 줄 지시**로 축소
- 크로스워크 사전 파싱률 **90% 내외** (미파싱 건은 수동 대상으로 분리 — 자동화 한계를 결과에 명시)
- 롤백 스냅샷 **20건 이상 축적** → 변경 이력으로도 기능
- 내 초기 구현의 전 조합 차단 → 부족 조합만 차단으로 고쳐 **판매 가능 재고의 불필요한 차단 제거**

<br>

## 이 케이스에서 실제로 배운 것

**"자동화의 어려움은 실행이 아니라 식별에 있다."**
어느 채널의 어느 옵션이 창고의 어느 물건인지를 기계가 확신할 수 없으면, 나머지 로직은 전부 위험해진다.
그래서 이 프로젝트의 절반은 제어 로직이 아니라 **사전 구축**이었다.

> 🔍 이 설계는 [재현 데모](../demo/)에서 더미 데이터로 직접 실행해볼 수 있습니다.
