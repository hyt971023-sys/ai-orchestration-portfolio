## 이 포트폴리오가 다루는 것

대부분의 자동화 포트폴리오는 **"무엇을 만들었는가"** 를 보여줍니다.
이 저장소는 그 앞뒤에 있는 세 가지를 보여줍니다.

### 1. 무엇을 자동화할지 어떻게 골랐는가
운영 업무를 감으로 자동화하면 **가장 눈에 띄는 일**부터 손대게 되고, 정작 조용히 손실을 내는 일은 남습니다.
저는 업무를 먼저 세고, 분류하고, 지표로 만든 다음 자동화했습니다.

→ **[업무 성숙도 4단계 프레임워크](docs/maturity-framework.md)** · **[측정 도구](tools/maturity/)**
`무인 자동` · `도구화` · `절차화` · `담당자 전속` 4단계로 분류하고, 별도 축으로 **실행 위치 집중도**를 측정합니다.

문서로만 두지 않고 **실행 가능한 도구**로 만들었습니다. CSV 한 장이면 그대로 돌아갑니다.

```bash
export PYTHONPATH=tools
python -m maturity sample > tasks.csv     # 예시 입력 생성
python -m maturity report tasks.csv       # 분포 · 두 지표 · 숨은 위험
```

특히 **「무인 자동인데 개인 환경에서 도는」 구간을 자동으로 뽑아냅니다.**
축을 하나만 쓰면 이 구간이 성과로 집계되기 때문입니다.

### 2. 자동화가 틀렸을 때를 어떻게 대비했는가
운영 자동화의 실패는 에러 메시지로 오지 않습니다. **아무 일도 일어나지 않는 형태**로 옵니다.

→ **[안전 설계 4원칙](docs/safety-design.md)** — 되돌릴 수 없으면 실행하지 않는다
→ **[조용한 실패 5유형 카탈로그](docs/silent-failure-patterns.md)** — 에러 없이 멈추는 자동화를 탐지하는 방법

### 3. 만든 것이 남에게 넘어갔는가
혼자 쓰는 자동화는 자산이 아니라 부채입니다. 담당자가 자리를 비우면 그대로 멈추기 때문입니다.

→ **[이관 설계](docs/handoff.md)** — 스킬·문서·가드레일로 실행 주체를 옮긴 기록

### 4. 내가 만든 것이 틀렸을 때 어떻게 알았는가
안전장치를 만든 사람은 그 안전장치를 검증할 수 없습니다. 같은 가정 위에서 만들었기 때문입니다.

→ **[케이스 06 — 내가 만든 안전장치가 실패했다](cases/06-gate-failure.md)**
이 저장소의 검사 게이트가 실패한 기록입니다. 발견은 제가 읽어서가 아니라 **밖에서 뚫어보게 해서** 나왔습니다.

## 재현 데모

실무 시스템은 공개할 수 없으므로, **핵심 설계를 더미 데이터로 처음부터 다시 구현**했습니다.

```bash
git clone https://github.com/hyt971023-sys/ai-orchestration-portfolio
cd ai-orchestration-portfolio
python -m demo "형광펜 A 옐로 재고 부족하니까 전 채널에서 막아줘"
```

3개의 가짜 채널 어댑터와 12개 가짜 SKU 위에서 다음을 실제로 보여줍니다.

- 자연어 지시 → 실행 계획으로 변환
- **dry-run 기본값** — 무엇이 바뀔지 먼저 출력
- 쓰기 전 **before 값 스냅샷** 저장
- 세트 상품의 **구성품 환산** (묶음 1개 = 구성품 N개)
- 이름이 겹치는 **구형·단종 옵션 제외** — 상품명이 아니라 바코드를 정본키로 (제외했다는 사실까지 출력)
- 쓰기 후 **독립 재조회(read-back)** — `200 OK`를 반영으로 믿지 않음
- 롤백 1회 실행
