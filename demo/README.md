# 재현 데모 — 자연어 오더 → 멀티채널 재고 오케스트레이션

실무에서 검증한 설계를 **더미 데이터로 처음부터 다시 구현**한 것입니다.
특정 회사의 코드·데이터·식별정보는 포함하지 않습니다.

```bash
python -m demo "형광펜 A 옐로 재고 부족하니까 전 채널에서 막아줘"
python -m demo "형광펜 A 옐로 막아줘" --apply            # 실제 반영
python -m demo --rollback demo/_snapshots/rollback-....json
python -m pytest demo/tests -q                            # 가드 검증 17건
```

## 이 데모가 보여주는 것

기능이 아니라 **안전장치**입니다. 각 항목은 [안전 설계 4원칙](../docs/safety-design.md)의 코드 구현입니다.

| 출력 | 무엇을 증명하나 |
|---|---|
| `채널 쓰기 가능 여부` | 설계 전에 채널 능력을 실측한다 — 조회만 되는 채널을 모르고 설계하면 절반이 수동으로 되돌아온다 |
| `크로스워크 N/M` | 매칭률을 숨기지 않는다. 미파싱은 수동 대상으로 분리 |
| `DRY-RUN` (기본값) | 무엇이 바뀔지 먼저 보여준다. 실행은 명시적 플래그 |
| `구성품 환산` | 세트 1개 = 낱개 N개. 묶음에 물리 재고를 그대로 걸면 배수로 팔린다 |
| `쓰기 미지원 채널` | 실패가 아니라 **수동 처리 대상**으로 분리 |
| `롤백 스냅샷` | 쓰기 전 before 값 저장. 저장 실패 시 **실행하지 않는다** |
| `반영 검증 4/4` | 쓰기 후 독립 재조회. `200 OK` 를 반영으로 믿지 않는다 |
| `이름이 겹치지만 제외한 단종 SKU` | 구형 옵션을 뺐다는 **사실까지 출력**한다. 조용히 빼면 "안 걸린 것"과 구분되지 않는다 |
| `partner:PT-A1 (형광펜A_01옐로(수출표기))` | 채널 표기가 달라도 바코드로 이어진다 — 이름으로는 못 잇는다 |

## 구조

```
demo/
├── catalog.py        정본 식별키(바코드) · 크로스워크 사전 · 세트 환산
├── planner.py        자연어 → 실행 계획 (교집합 매칭, 못 찾으면 중단)
├── orchestrator.py   실행 · 스냅샷 · read-back 검증 · 롤백
├── adapters/         채널 어댑터 3종 (쓰기 가능 2 + 조회 전용 1)
├── fixtures/         가짜 SKU 12개(구형·단종 2건 포함) · 가짜 채널 리스팅
│                     바코드는 체크디지트를 무효로 둔 더미 (실물 조회 불가 — 테스트로 고정)
└── tests/            가드 검증 17건
```

## 설계 결정 기록

**Q. 왜 LLM 을 호출하지 않고 결정적 파서를 썼나**
포트폴리오 데모는 누가 언제 돌려도 같은 결과가 나와야 합니다. 그리고 이 케이스의 핵심은 모델이 아니라 **그 앞뒤의 안전장치**입니다.
실무에서는 `planner.parse()` 자리에 코딩 에이전트가 들어가고, 산출물은 동일한 `Plan` 객체입니다. 오케스트레이터는 바뀌지 않습니다.

**Q. 왜 검색어를 교집합(AND)으로 좁히나**
합집합으로 하면 "형광펜 A 옐로"가 형광펜 A **전 색상**을 잡습니다.
한 옵션만 부족한데 전 조합을 닫으면 **팔 수 있는 재고를 스스로 막는 것**입니다.

**제가 처음 만든 구현이 상품 단위로 전 조합을 닫았습니다** — 합집합과 결과가 같습니다
([케이스 01 ④](../cases/01-stock-orchestration.md)).
왜 틀렸는지 알고 나서 조합 단위로 좁혔고, 같은 실수를 다시 하지 않도록 테스트로 고정했습니다.
교집합이 비면 넓히지 않고 중단합니다 — 넓히는 순간 의도하지 않은 대상이 섞입니다.

**Q. 픽스처에 왜 `(구형)`·`(단종)` 옵션을 남겨 뒀나**
빼면 데모가 쉬워지지만, 이 케이스의 어려움 자체가 사라집니다.
`01 옐로` 와 `01 옐로 (구형)` 은 **이름으로는 구분되지 않고**, 구형 리스팅은 채널에 판매 상태로 남아 있습니다.
그래서 데모는 두 결과를 함께 계산합니다 — 상품명으로 골랐다면 무엇이 걸렸을지, 바코드로 골라서 무엇이 빠졌는지.
그 차이가 `이름이 겹치지만 제외한 단종 SKU` 로 출력됩니다.

**Q. 왜 진열(displayed)은 안 끄나**
진열까지 끄면 상품이 목록에서 사라져 되돌아올 경로를 잃습니다. **판매만 막고 존재는 남깁니다.**

**Q. 왜 노출 플래그가 아니라 판매 플래그를 쓰나**
품절 표시만으로는 실제 주문이 막히지 않는 채널이 있습니다. **차단의 정의를 "주문이 안 되는 상태"로** 잡아야 합니다.
